Tool approval in the SDK is a high-level API built on top of hooks. Hooks
suspend the loop until your application resolves them externally with some
payload.

## Require tool approval

Pass `require_approval=True` to `@ai.tool` when a tool needs approval:

```python
@ai.tool(require_approval=True)
async def notify_mothership(message: str) -> str:
    """Notify the mothership."""
    return f"Sent: {message}"
```

When the model calls the tool, the agent emits a `PendingHookEvent`. Resolve
it with `ai.resolve_hook`:

```python
async with agent.run(model, messages) as stream:
    async for event in stream:
        if isinstance(event, ai.events.PendingHookEvent):
            print(event.hook.hook_id, event.hook.metadata)
            ai.resolve_hook(
                event.hook,
                ai.tools.ToolApproval(granted=True, reason="approved"),
            )
```

Return a denial by resolving the hook with `granted=False`:

```python
ai.resolve_hook(
    "approve_tool_call_id_here",
    ai.tools.ToolApproval(granted=False, reason="not allowed"),
)
```

Cancel a live hook when the waiting workflow should stop:

```python
await ai.cancel_hook("approve_tool_call_id_here", reason="client disconnected")
```

Cancellation stops the waiting tool without adding a tool result. The history
can end with an unanswered tool call; in that case, `stream.output` is not
available. Resolve with `granted=False` instead when you want the model to
continue after a denial.

Hook operations target the current `HookRegistry`, which is set inside the
`async with agent.run(...)` block. To resolve from a different task — a UI
callback, another endpoint — pass a registry explicitly. Create one up front
and hand it to the run (or use the run's own via `stream.hook_registry`):

```python
registry = ai.HookRegistry()

async with agent.run(model, messages, hook_registry=registry) as stream:
    ...

# elsewhere, e.g. in a UI callback:
ai.resolve_hook(hook_id, approval, registry=registry)
```

`ai.get_hook_registry()` returns the current registry (raising `LookupError`
when there is none), which is handy to capture the run's registry without
threading `stream` around:

```python
async with agent.run(model, messages) as stream:
    on_approval_needed(registry=ai.get_hook_registry())
    ...
```

To make a registry current for a block of code outside a run — so plain
`resolve_hook(...)` calls inside it need no `registry=` argument — use
`ai.agents.hooks.use_hook_registry`. It is an async context manager and
also works as a decorator on async functions:

```python
from ai.agents import hooks

async with hooks.use_hook_registry(registry):
    ai.resolve_hook(hook_id, approval)

@hooks.use_hook_registry(registry)
async def on_decision(hook_id: str, approval: ai.tools.ToolApproval) -> None:
    ai.resolve_hook(hook_id, approval)
```

## Build custom hooks

Use `ai.hook` to define your own custom hooks to suspend execution
and deliver external information into the loop:

```python
class CustomPayload(pydantic.BaseModel):
    foo: int

approval = await ai.hook(
    "some_hook",
    payload=CustomPayload,
    metadata={"request_type": "operator_review"},
)
```

Resolve the hook from another part of your application:

```python
ai.resolve_hook(
    "some_hook",
    {"foo": 999},
)
```

## Resume in serverless flows

For an initial request that must end while a hook waits, call `ai.defer_hook`
on each `PendingHookEvent`. The run ends in a blocked state instead of waiting
for a resolution in the same process.

On the first request, drain the stream and save the full runtime history,
including internal messages. `stream.blocked` tells you whether the run needs
external input. `stream.deferred_hooks` holds the hooks to show to the caller:

```python
from typing import Any


async def start_run(
    agent: ai.Agent,
    model: ai.Model,
    messages: list[ai.messages.Message],
) -> dict[str, Any]:
    async with agent.run(model, messages) as stream:
        async for event in stream:
            if isinstance(event, ai.events.PendingHookEvent):
                ai.defer_hook(event.hook)

    state = {
        "messages": [message.model_dump(mode="json") for message in stream.messages],
        "blocked": stream.blocked,
        "hooks": [hook.model_dump(mode="json") for hook in stream.deferred_hooks],
    }
    if not stream.blocked:
        print(stream.output)
    return state
```

Persist the returned state in your application's store before ending the
request. Do not read `stream.output` while the run is blocked: it has no final
assistant output yet. The run's `stream.hook_registry` is an in-process
registry, not the history you persist.

On the next request, load the saved state and accept authenticated decisions
from the caller. Pass each stored hook ID and its payload to `ai.resolve_hook`
inside the new run, before iteration. Supply decisions for all saved hooks
together: a current SDK defect can leave `stream.blocked` false if a replayed
turn defers again, so this helper can raise `ValueError` instead of returning
state.

```python
from typing import Any


async def resume_run(
    agent: ai.Agent,
    model: ai.Model,
    saved_state: dict[str, Any],
    decisions: dict[str, ai.tools.ToolApproval],
) -> dict[str, Any]:
    messages = [
        ai.messages.Message.model_validate(item) for item in saved_state["messages"]
    ]
    async with agent.run(model, messages) as stream:
        for hook_id, payload in decisions.items():
            ai.resolve_hook(hook_id, payload)

        async for event in stream:
            if isinstance(event, ai.events.PendingHookEvent):
                ai.defer_hook(event.hook)

    state = {
        "messages": [message.model_dump(mode="json") for message in stream.messages],
        "blocked": stream.blocked,
        "hooks": [hook.model_dump(mode="json") for hook in stream.deferred_hooks],
    }
    if not stream.blocked:
        print(stream.output)
    return state
```

For example, an operator's approval becomes
`ai.tools.ToolApproval(granted=True, reason="approved")`. Custom hooks use their
declared payload type instead. Check that each decision belongs to the current
user and saved run before registering it.

The loop replays saved model responses and completed tool results. It continues
when it reaches a hook with a pre-registered resolution. Keep tools and custom
loop behavior consistent between requests so replay can match the saved history.
